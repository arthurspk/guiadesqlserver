## 🗺️ Roadmap

- [roadmap.sh — SQL Roadmap](https://roadmap.sh/sql) — Roadmap da linguagem SQL: do SELECT básico a janelas, índices e transações — aplicável integralmente ao dialeto T-SQL do SQL Server.
- [Microsoft Learn — Catálogo de treinamentos SQL Server](https://learn.microsoft.com/pt-br/training/browse/?terms=sql%20server) — Índice oficial de todos os módulos e trilhas de treinamento gratuito da Microsoft sobre SQL Server.
- [Microsoft — Editions and supported features of SQL Server 2022](https://learn.microsoft.com/en-us/sql/sql-server/editions-and-components-of-sql-server-2022?view=sql-server-ver17) — Comparativo oficial de edições (Express, Standard, Enterprise) e recursos suportados em cada uma.
- [Microsoft — SQL Server 2022 release notes](https://learn.microsoft.com/en-us/sql/sql-server/sql-server-2022-release-notes?view=sql-server-ver17) — Notas de lançamento oficiais com todas as novidades da versão mais recente estável.
- [Microsoft — O que há de novo no SQL Server 2025](https://learn.microsoft.com/pt-br/sql/sql-server/what-s-new-in-sql-server-2025?view=sql-server-ver17) — Página oficial com as novidades da versão mais recente do SQL Server, incluindo recursos de IA nativos.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos** — o que é um SGBD relacional, instâncias, bancos de dados, tabelas, chaves primária e estrangeira.
2. **T-SQL básico** — `SELECT`, `WHERE`, `ORDER BY`, `INSERT`, `UPDATE`, `DELETE`, `CREATE TABLE`, tipos de dados do SQL Server.
3. **T-SQL intermediário** — `JOIN`, `GROUP BY`, subconsultas, CTEs (`WITH`), views, funções de janela (`OVER`, `PARTITION BY`).
4. **Programação T-SQL** — stored procedures, functions, triggers e tratamento de erro (`TRY...CATCH`).
5. **Performance** — índices clustered/nonclustered, planos de execução, Query Store, estatísticas.
6. **Administração** — instalação, SSMS, logins e permissões, backup e restore, jobs no SQL Server Agent.
7. **Alta disponibilidade e escala** — Always On Availability Groups, log shipping, replicação, failover clusters.
8. **Nuvem e IA** — Azure SQL Database, SQL Server on Azure VM, Copilot no SSMS e uso de IA para escrever e revisar T-SQL.

## 🤖 IA na prática

O SQL Server é, hoje, um dos bancos com IA mais integrada nativamente às suas próprias ferramentas: o **Copilot dentro do SSMS** já entende o esquema conectado e sugere T-SQL sem sair da tela de consulta. A regra de ouro continua a mesma: a IA propõe, o plano de execução e um ambiente de teste decidem.

**Para aprender**
- Cole uma consulta que você não entende e peça para a IA explicar cláusula por cláusula e reescrever com CTEs para ficar mais legível.
- Cole um erro (ex.: `Invalid column name` ou `Incorrect syntax near`) junto com a consulta e peça a causa e duas formas de corrigir.
- Descreva um sistema (ex.: "um e-commerce com pedidos, clientes e produtos") e peça o modelo lógico e o `CREATE TABLE` em T-SQL — depois critique: faltou índice? o tipo de coluna está certo (`NVARCHAR` vs `VARCHAR`)? deveria ter uma chave estrangeira?
- Peça exercícios com gabarito sobre o tópico que está estudando (window functions, CTEs recursivas, stored procedures) usando o AdventureWorks como base.
- Peça para explicar, operador a operador, a saída de um plano de execução real (Actual Execution Plan).

**Para trabalhar**
- **Copilot no SSMS**: desde as versões 21/22, o Copilot conversa dentro do próprio editor de consultas, entende o schema conectado e — em modo agente — pode investigar categorias de espera, consultas lentas e uso de recursos direto no Pesquisador de Objetos. Toda sugestão deve ser revisada antes de rodar, principalmente `UPDATE`/`DELETE`.
- **mssql para VS Code**: com a aposentadoria do Azure Data Studio, o caminho oficial da Microsoft para consultar e administrar SQL Server com IA fora do SSMS passou a ser o VS Code com a extensão `mssql`, combinada com GitHub Copilot.
- **Copilot in Fabric**: para quem trabalha com SQL Server/Azure SQL integrado ao Microsoft Fabric, o Copilot ajuda a gerar consultas e a explicar modelos de dados em linguagem natural.
- **SQL-AI-samples (Microsoft)**: repositório oficial com exemplos de servidores MCP, RAG e text-to-SQL conectados a SQL Server/Azure SQL — ponto de partida para conectar assistentes como Claude Code ou Copilot ao seu banco com controle de permissões.
- **Text-to-SQL** já é produto: [Vanna](https://vanna.ai/) e [WrenAI](https://github.com/Canner/WrenAI) transformam perguntas em consultas SQL, com suporte a SQL Server. Funciona bem para explorar dados; para relatórios oficiais, revise sempre.
- Use assistentes de IA para: escrever stored procedures, gerar dados de teste (massa de dados), criar índices a partir de um plano de execução lento, documentar tabelas e escrever testes de consultas.

**Limites e boas práticas**
- LLMs **inventam colunas, tabelas e procedures** que não existem. Sempre forneça o esquema (`sp_help 'tabela'` ou o schema exportado) no prompt.
- Uma consulta "correta" pode ser **lenta ou perigosa** (table scan em tabela grande, `DELETE` sem `WHERE`, `UPDATE` em milhões de linhas). Rode em ambiente de teste, dentro de uma transação (`BEGIN TRAN` / `ROLLBACK`), e leia o plano de execução antes de aplicar em produção.
- Text-to-SQL erra mais em bancos reais do que em benchmarks — ambiguidade de negócio ("clientes ativos" significa o quê?) é a principal causa de erro.
- **Nunca cole dados pessoais ou segredos** (senhas, connection strings, dados de clientes) em ferramentas de IA sem a política de segurança da sua empresa. Lembre-se da LGPD.
- Entenda o que você executa: em produção e em entrevista técnica, a consulta é sua.
